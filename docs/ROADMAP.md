## P0 — 真上线前必须做

### 1. 前端从未在浏览器里跑过

代码能构建、接口都验证过，但**没有人真正打开过管理后台**。构建通过 ≠ 页面可用。

- 为什么：这是唯一一处「写了但没看过」的地方，出错概率最高。
- 验收：Playwright 冒烟脚本（登录 → 四个角色各自的落地页 → 发码 → 交付 → 远程授权批准 →
  语言切换），任一页出现 console error 即失败；跑通后截图归档到 `docs/`。

### 2. 单机部署与备份恢复在目标机验证

Compose 只在开发机跑过，`docs/OPERATIONS.md` 里的恢复演练不是最近一次的镜像。

- 为什么：备份没恢复过 = 没有备份。
- 验收：新机器上从零执行「起服务 → 迁移 → 恢复最近备份 → `scripts/smoke.sh` 全绿」，
  过程与耗时写进 OPERATIONS.md；备份改为定时任务（cron/systemd timer）+ 异地一份。

### 3. 真实邮件投递验证

默认走 `ConsoleChannel`；没有在部署机配 SMTP 并对真实邮箱发过一封。

- 为什么：邮件是「到期提醒」「发码交付」的唯一出口，投递不通只有日志里能看到。
- 验收：部署机配好 SMTP，后台「设置 → 通知模板」点预览无误，再对真实邮箱发一封发码邮件；
  outbox 状态从 `pending` 走到 `sent`。

### 4. 账号安全

密码策略已补（≥10 位 + 三类字符 + 弱口令表 + 禁止含邮箱账号名，只约束新设密码）；
**MFA 还没有**——管理员账号一旦泄露仍是整租户沦陷。

- 剩余验收：可选 TOTP 二次验证 + 登录成功/失败通知（已有邮件通道与模板，可直接复用）。

### 5. 暴露面检查

`/metrics` 无鉴权、CORS 与限流覆盖不全。

- 验收：`/metrics` 只能内网或带 token 访问；对外只暴露必要端口；
  所有写接口都在限流覆盖表里；写一份「对外端口与鉴权一览」。

### 6. 发布与回滚

现在只能前滚：`git pull && build && restart`，迁移没有 down 演练。

- 验收：发布脚本（构建 → 迁移 → 健康检查 → 失败回滚到上一个镜像 tag）；
  每个迁移文件写死可执行的 `-- migrate:down`，并至少演练一次真实回滚。
